# v0.4 CI / public v0.3.9 release-boundary repair

Date: 2026-08-02

## Decision

The public v0.3.8 line-ending bridge and v0.3.9 release manifest remain
byte-frozen. They are historical release contracts and must not be regenerated
against the mutable v0.4 reference catalogue.

CI is split into two explicit verification domains:

- the current lane checks Ruff, `scripts/reproduce_v04.py`, and current-tree
  tests;
- the historical lane checks out the exact public v0.3.9 source commit
  `cba86eae795e1e985c4ba1bcd3dabe4eb2773fab`, with full Git history, and runs
  `scripts/reproduce_v039.py` plus the four release-relative test files there.

The four historical tests excluded only from the current-tree Pytest command
are:

- `tests/final_theory/test_reproduce_v037.py`;
- `tests/final_theory/test_line_ending_bridge_v038.py`;
- `tests/final_theory/test_reproduce_v038.py`;
- `tests/final_theory/test_reproduce_v039.py`.

They remain mandatory in the historical lane. This is version isolation, not
test deletion.

## Current v0.4 line-ending normalization

The current-tree line-ending test also exposed six mutable v0.4.2 JSON writers
whose default text mode emitted CRLF on Windows. Each writer now explicitly
uses `newline="\n"`, and its checked-in artifact was regenerated. JSON content
and all intrinsic semantic digests remained unchanged except for the D12
manifest: it deliberately binds the raw SHA of its state-native chart input,
so the canonical-LF input changed the D12 semantic digest to
`82cd51ddd29e5923b003c8cf8f75a5a26cf5a36edf68728ad58d298d3f573090`.

The fixed-vector escape artifact's canonical-LF raw SHA is
`6c8b230fc4c4a8c2a0d4f352da846b633639ecf59f0ef67537a53b5dedb229a6`.
These are current v0.4 bookkeeping changes and do not alter either frozen
public artifact above.

## Operational rule

Future public releases receive a new versioned bridge or release manifest.
Never move an old bridge's expected hashes forward to accommodate a mutable
research tree. Tracked program sources need no separate NAS mirror because Git
push is the operational backup; the NAS remains cold storage for preserved
papers and expensive non-Git artifacts and is never an execution location.
