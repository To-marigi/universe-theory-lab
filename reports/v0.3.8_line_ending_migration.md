# v0.3.8 canonical-LF migration

## Outcome

v0.3.8 repairs a byte-serialization defect in the local v0.3.7 release
candidate.  It does not change a scientific artifact's decoded JSON value,
rerun a Sage computation, or change a scientific verdict.

The v0.3.7 artifacts were written with CRLF bytes on the originating Windows
checkout.  Raw SHA-256 fields embedded in later artifacts therefore committed
to the CRLF serialization, although Git stored canonical LF and reproduced LF
on Linux.  A clean checkout could preserve the JSON values while failing the
raw-byte hash gates.

## Compatibility bridge

`results/v0.3.8_line_ending_bridge.json` is a deterministic compatibility
ledger.  It contains:

- 1,007 legacy raw-byte bindings;
- 84 JSON consumers;
- 207 canonical-LF target files;
- 1,027 candidate edges, including 20 bindings with byte-identical target
  candidates.

Every binding is located by an RFC 6901 JSON Pointer.  Each recorded value is
checked against the SHA-256 of a target's virtual CRLF serialization.  Semantic,
request, expression, polynomial, and budget identities are excluded from this
raw-byte classification.

The legacy resolver is explicitly path based:

- a declared bridge target resolves to its virtual-CRLF SHA-256;
- every other path resolves to its current raw-byte SHA-256.

Digest coincidence cannot silently opt an unrelated path into the bridge.

## Historical manifest boundary

The immutable `results/v0.3.7_release_manifest.json` remains a historical
record.  Its 159 entries are audited, rather than regenerated as a current
manifest:

- 52 still match their recorded raw bytes;
- 81 match through the declared CRLF-to-LF bridge;
- 26 are explicitly classified v0.3.8 writer, test, metadata, or support
  updates;
- 0 are unexplained changes.

The 26 support/source changes add canonical-LF writer arguments, bridge-aware
regression tests, release metadata, or repository line-ending policy. They
are not proof-certificate changes. The new
`results/v0.3.8_release_manifest.json` records the current canonical-LF raw
bytes and excludes itself.

## Scientific regression

On the canonical-LF checkout, the compatibility resolver passes the existing
strict checks:

- Phase 1: `LITERAL_Q1_Q4_COMMUTATIVITY_PROVED`, including all 63 certificate
  bindings and the 21-chart exact QQ proof;
- Phase 2: `LEMMA_GENERAL_SCALAR_CHAIN_FIBER_EXACT`, including both exact QQ
  branch certificates;
- scope addendum: `V037_SCOPE_ADDENDUM_CERTIFIED`, with its frozen semantic
  digest unchanged;
- global scientific verdict: `FINAL_THEORY_OPEN`.

Thus the v0.3.8 migration is byte-serialization-only.  It does not broaden the
finite, non-singular, strong-operator claim boundary of v0.3.7.

## Local verification

On 30 July 2026, the canonical-LF worktree passed:

- `scripts/reproduce_v038.py`, including exact bridge and manifest regeneration;
- the complete pytest suite, 341 tests;
- the complete Ruff check;
- the tracked-text audit with zero CRLF and zero mixed-EOL files;
- ZIP validation of the vendored wheel against the unchanged Git blob.

The v0.3.8 manifest contains 193 files and excludes itself.  The advisory mypy
job still reports the same 11 pre-existing errors in
`d2_sage_backend_v035.py`; no new typing error was introduced by this
migration.

## Release rule

The v0.3.8 manifest, bridge, tests, and reproducer must pass on a clean
canonical-LF checkout before any external deposit.  The historical v0.3.7
manifest is never rewritten to make its raw digests look current.
