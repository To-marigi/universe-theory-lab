# v0.3.9 audit ref portability

Status: **`V039_AUDIT_REF_PORTABILITY_FIXED`**
Scientific change: **`NONE`**

## The defect

`baseline_audit_v0_3_1` resolved the frozen v0.3 branch with a bare
`git rev-parse codex/final-theory-v0.3-novelty-first-20260728`.

Git's revision rules try `refs/<name>`, `refs/tags/<name>`, `refs/heads/<name>`
and `refs/remotes/<name>`, but never `refs/remotes/origin/<name>` for a bare
name.  `git clone` and `actions/checkout` create a local head only for the ref
they check out, so in any clone the frozen branch exists solely as
`refs/remotes/origin/...` and the bare resolution fails.

The audit therefore passed only where that local head had been created by hand.
It was verifiable on the authoring machine and nowhere else — the same class of
defect as the CRLF raw-byte hashes fixed in v0.3.8 and the unpublished refs
fixed alongside it.

Observed as `ENGINEERING_STATUS: ENGINEERING_FAIL` in CI run 30544994303, which
reached 339 passed / 2 failed:

```text
test_audit_v031.py::test_v03_baseline_is_immutable
test_v031.py::test_v031_gate_statuses_and_claim_ceiling
```

The annotated freeze tag resolved correctly throughout, which is why the v0.2
audits passed and only the v0.3 ones failed.

## The fix

`audit_v031.resolve_frozen_branch` tries the bare name first, so a checked-out
working copy is unaffected and a local head still takes precedence, then falls
back to `refs/remotes/origin/<branch>`.  Both paths resolve to the same commit,
so every recorded audit value is unchanged.

The v0.3.8 workaround is removed: CI no longer creates the local head, and
`REPRODUCING_v0.3.9.md` carries no prerequisite section.

## Boundary

The fallback is `origin`-specific by choice.  A full clone with the conventional
remote name is in scope; arbitrary remote names are not generalised over, and
that limit is stated in `REPRODUCING_v0.3.9.md` rather than left implicit.  A
shallow clone remains insufficient for every baseline audit, since the freeze
commits and annotated tags must be present as objects.

## Evidence

Five regression tests in
`tests/final_theory/test_audit_ref_portability_v039.py` build a repository whose
branch exists only as `refs/remotes/origin/<name>` and pin: that a bare
`rev-parse` cannot see it, that the resolver can, that a genuinely absent branch
still fails rather than resolving to something else, that a local head takes
precedence, and that the real repository still resolves to
`3ccbc66cc2cf868bf2a33ab96d4dd46e729d5f09`.

End-to-end, a fresh clone of the repository at `51887c2` with no local head for
the frozen branch reports:

```text
refs/heads/<frozen branch>   ABSENT
frozen_branch_target         3ccbc66cc2cf868bf2a33ab96d4dd46e729d5f09
v03_artifacts_unchanged      True
verdict                      V0_3_BASELINE_LOCK_PASS
passed                       True
```
