# v0.4.2 source-stage MSR to Q-level lift audit

## Decision

`msr:p1-0`, `msr:p2-0`, and `msr:p2-2` do have an exact and unique existing
source-to-Q lift.  Each lift is the zero expression.  Consequently none is a
missing single Q-level direct equation, and a proposed ``700 CPOBC + one of
these MSR labels'' campaign would add no equation to the v0.3.5 direct ideal.
It must not be run or reported as a one-MSR test.

This began as a source-label/direct-relation namespace mismatch, but it also
exposes a semantic defect in the v0.4.1 proof interpretation.  Eq. (108) is an
MSR-dependent elimination and was fixed before relation-family filtering;
symmetrically, Eq. (112) fixed strong-GC-dependent coordinates.  See
`v0.4.1_scope_break_decision_packet.md`.  The calculation below is exact in
the noncommutative word algebra; no solver was invoked.

## Existing provenance path

The complete forward path already exists:

```
v0.3.1 source MSR constraint
  -- term transition_id --> v0.3.2 165-occurrence Eq.(107)/(108) reduction
  -- exact word sum --> v0.3.2 rewritten_MSR_inventory
  -- split zero/nonzero --> v0.3.3 strong_MSR_identities/residuals
  -- retain residuals only --> v0.3.5 direct operator system
  -- matrix entries --> d2_sage_backend_v035 selected_relations
```

`cpobc_v031._msr_operator_constraints` constructs one source constraint per
source causet by summing the transition-orbit representatives with their
`precursor_orbit_size` multiplicities and subtracting the identity.
`cpobc_d2_v032._rewritten_msr_inventory` then substitutes the 165 exact
occurrence expressions, preserving word order.  The compiler reports 24 MSR
constraints = 3 free-word identities + 21 residual constraints.  The v0.3.3
presentation keeps those partitions separately.  Finally,
`d2_solver_v034._specialised_relation_inventory` appends only
`strong_MSR_residuals`; this is why the v0.3.5 system has exactly 21
`STRONG_OPERATOR_MSR` records, all at source stages 3 or 4.

The Sage backend correctly selects only `relation_id`s present in this final
direct artifact.  It has no source-MSR-to-relation-ID translation step, and
it should not invent one.

## Exact lifts of the three scout labels

Write `I` for the empty word and `G=G_{p2-2}`.  The following are the exact
v0.3.2 expressions read through the source constraint's `transition_id`s.

| source constraint | source-MSR lift before cancellation | Q-level result |
| --- | --- | --- |
| `msr:p1-0` | `Q1 + (I-Q1) - I` | `0` |
| `msr:p2-0` | `Q2 + 2(-Q1 Q2 Q1^-1 + Q2 Q1^-1) + (I + 2 Q1 Q2 Q1^-1 - Q2 - 2 Q2 Q1^-1) - I` | `0` |
| `msr:p2-2` | `G + (G Q1^-1 - Q1 G Q1^-1) + (I - G - G Q1^-1 + Q1 G Q1^-1) - I` | `0` |

The three records have no missing occurrences, `reduced_residual: []`, and
the canonical empty-expression SHA-256
`4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945`.
They are exactly the three entries in v0.3.3
`relation_inventory.strong_MSR_identities`.  Neither v0.3.5 branch contains
any of these three IDs.  In each branch its 1001 direct records split as
700 CPOBC, 21 strong MSR residuals, 255 local strong-GC residuals, and 25
Eq.(112) path-consistency relations.

Thus the three candidate labels are a minimal concrete counterexample to the
assumption that a source MSR label names one direct Q-level relation: the
source constraint is nonempty (two, three, and three transition terms,
respectively), yet its exact direct residual is zero.

## Consequence for v0.4.2

The triangular scout can still be useful as a heuristic for selecting a
**source constraint**, but it did not select a nontrivial Q-level MSR
relation.  The stated single-MSR project cannot be tested with any of these
three candidates.  The valid next choices are:

1. Re-run the scout while restricting its candidate universe to the 21
   nonzero v0.3.3 `strong_MSR_residuals`; then a one-relation direct campaign
   has an unambiguous `relation_id`.
2. If minimality is intentionally source-level, construct a dedicated
   source-stage compiler that retains all 165 transition variables and the
   Eq.(107)/(108) definitions, then tests a source-MSR constraint before
   quotienting.  Its theorem must explicitly be source-level, not a claim
   about adding one direct Q relation.

The first route is meaningful only as relation redundancy inside the existing
strong-profile Q presentation. It cannot repair either one-sided semantic
theorem. A semantic repair requires profile-native coordinates as described
in the v0.4.1 decision packet.

## Minimal provenance compiler design (if source-level testing is retained)

An append-only compiler should emit one record per source MSR constraint:

```json
{
  "source_constraint_id": "msr:p2-0",
  "source_artifact_sha256": "...",
  "transition_terms": [{"transition_id": "...", "coefficient": 2}],
  "reduction_map_digests": [{"transition_id": "...", "sha256": "..."}],
  "q_residual": [{"coefficient": 1, "word": ["Q_2"]}],
  "q_residual_sha256": "...",
  "classification": "IDENTITY_AFTER_EQ107_EQ108",
  "direct_relation_id": null
}
```

For a nonzero residual, `direct_relation_id` must equal the matching v0.3.3
`strong_MSR_residuals.constraint_id`, with an identical residual digest, and
must occur in both v0.3.5 relation branches.  For an identity it must be
`null`; fabricating an ID is a verification failure.  Required mechanical
checks are: all 24 source IDs occur once; every referenced transition is one
of the 165 reduction-map occurrences; word sums reproduce the v0.3.2
residual/digest; the partition is 3 identities + 21 residuals; and direct
membership agrees with the partition.  The new focused test added with this
note performs these checks for the three v0.4.2 scout candidates.
