## What this readback does not change

`zenodo/paper1-v0.4.2/owner_decision.json` and `metadata.template.json`
still record `release_gates` as all `false`, `publication_date`, `doi`, and
`final_commit` as `null`, and `status =
OWNER_DECISIONS_RECORDED_RELEASE_ACTIONS_PENDING`. Those fields, and the
matching fail-closed checks in `build_paper1_bundle.py` /
`verify_paper1_bundle.py` (`expected_gates` all `false`, the
`OWNER_DECISIONS_RECORDED_RELEASE_ACTIONS_PENDING` status literal), are
**not** updated by this record, because doing so is a deliberate pipeline
change, not an incidental one: this repository's Zenodo tooling was built
specifically to gate and fail closed on a release that had not yet happened.
Now that it has happened, reconciling `owner_decision.json` to the true
post-publication state requires rewriting those fail-closed contracts (the
`expected_gates` literal, the status-string checks in both builder and
verifier, and the corresponding assertions in
`tests/test_paper1_zenodo_bundle_v042.py`) rather than a one-line edit, and
is left as an explicit open follow-up for the owner to request rather than
performed as a side effect of this readback.

Until that follow-up is done, `owner_decision.json` is stale relative to
reality: it should be read alongside this record, not as the current source
of truth for whether the paper has been published.
