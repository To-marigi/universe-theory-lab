# v0.4.2 SR2V auxiliary ideal determinantal pilot 実測報告

- 記録日: 2026-08-05
- 対象: SR2V `q=5` free auxiliary ideal、chart `U2`
- 係数体: `GF(32003)`（有限体 scout）
- 実装方式: `determinantal_inventory_v1` / `determinantal_cegar_v1`
- 位置づけ: 第一論文の補助イデアル閉鎖に対する go/no-go 判定
- 結論: 計算経路は実用域まで改善したが、stage 7 subset は証明に不十分であり、第一論文の定理は未閉鎖

## 1. 結論

従来の `h A_i + B_i` を直接 Gröbner/saturation に投入する方式を、`h` を持たない 52 変数環上の entry ideal、2 行列式 ideal、radical membership に分解した。全 minor を生成せず、unit-associate row の厳密な正規化、費用順 minor inventory、prefix ごとの局所化、各 `A_i` の radical membership を bounded CEGAR として実装した。

stage 1、4、7 を監督付きで実行した。stage 7 は旧 direct system route が `125.718` 秒で timeout し最初の chart saturation を完了できなかったのに対し、新経路は `52.218` 秒で entry localization、3 個の非零 minor、3 prefix、全 4 radical target の判定を完了した。campaign の15秒間隔 sample は旧 `551,026,688` bytes、新 `277,453,209` bytes だったが、新 worker 自身の `ru_maxrss` は `353,112 KiB`（約361.6 MB）であり、sample が一時 peak を逃している。したがって確定的に主張するのは、旧 route の timeout に対して新 bounded scout が完了したことと、観測 memory が低下したことだけである。両者は同一アルゴリズムの同一処理ではないため、この比率を full solver 一般の速度倍率とは主張しない。

数学的結果は `DETERMINANTAL_SUBSET_INCONCLUSIVE` である。entry ideal は unit ではなく、各 minor prefix でも全 radical target が偽だった。これは選択 subset が十分条件を満たさなかったことだけを意味し、full 543 row 問題が non-unit であることを意味しない。GF scout が正方向に通っていないため QQ 計算・direct lift は開始していない。

したがって、合意済み計画の go/no-go 判定は完了したが、第一論文化の閉鎖条件は未達である。次は blind な stage 8 ではなく、未閉鎖成分から exact escape row を抽出し、全 543 unique rows を streaming 評価して追加 row/minor を選ぶ段階である。そこで進展が得られない場合は、resource-open として境界を正式固定する。

## 2. 数学的根拠と claim boundary

局所化済み可換環を `R`、有限個の row を `(A_i,B_i)` とし、

```text
J = <h A_i + B_i>  subset R[h]
E = <A_i, B_i>     subset R
D = <A_i B_j - A_j B_i : i < j> subset R
```

とする。このとき、単位元を持つ任意の可換環上で

```text
J = R[h]  <=>  E = R  and  A_i in radical(D) for every i
```

が成り立つ。domain、reduced、Noetherian の仮定は不要である。本プロジェクトへの適用では、正しい localized ring、row universe の binding、unit による row clearing、全 prime/residue field 上の量化を維持する。

選択 row 集合 `S` に対して上の条件を証明すれば `J_S=R[h]` であり、`J_S subset J_full` なので full unit ideal の十分条件になる。一方、subset 条件の不成立、properness、timeout は full 問題について非結論である。

また、選択 minor ideal 自体が localized unit ideal なら、各 minor

```text
A_i(hA_j+B_j) - A_j(hA_i+B_i) = A_i B_j - A_j B_i
```

が `J` に入るため、直ちに full unit ideal の十分条件になる。単なる非零 minor、点評価での非零、gcd 1 は代用にならず、exact localized unit certificate が必要である。

GF 上の正結果は method-selection scout に限る。QQ 上で同じ条件を exact に再計算し、さらに承認済み schema の lift identity を独立再検証するまでは terminal theorem/certificate に昇格しない。今回、その前提となる GF pass がない。

この節はプロジェクト内の独立導出であり、今回の作業に外部文献・Web 資料は使用していない。

## 3. 実装した計算設計

### 3.1 h-free 表現と bounded materialization

- determinantal method は `t1..t4,s0..s47` の 52 変数環を使い、`h` を生成しない。
- frozen input は 1,127 source rows から zero 336、duplicate 248 を除いた 543 unique rows である。
- full row pair の `A` は 7,589,236 terms、`B` は 5,081,569 terms、計 12,670,805 terms で、`max_loaded_terms=5,000,000` を超える。したがって full rows/minors は一括 materialize しない。
- stage ごとに必要な polynomial IDs だけを stream し、stage 1/4/7 の live basis cap をそれぞれ 10,000 / 50,000 / 100,000 terms、generated minor cap を 10,000 / 20,000 / 40,000 terms に固定した。stage 8 以降も 100,000 / 40,000 を維持し、旧 global cap 5,000,000 / 1,000,000 へ暗黙に緩和しない。

### 3.2 row/minor 正規化

- `(A_i,B_i)` の零 row と ground-field unit associate を exact に判定し、代表 row と係数関係を certificate に残す。
- representative row のうち最小 cost row を pivot とする star minors を先に並べ、その後に non-star pairs を cost 順に並べる。
- minor は materialize 後に零および ground-field unit associate を exact に除去する。
- 各 minor の積項数上界を生成前に累積し、policy cap を超える次の minor は乗算前に停止する。生成後の actual term cap も二重に検査する。
- prefix schedule は `1,2,4,all` を上限として、存在する候補数で切る。

### 3.3 exact saturation と status

- libSingular `sat_with_exp` を `isSB=1` で呼び、各 localization factor 後に input containment と exponent identity を検証する。
- entry ideal が unit、または minor ideal が unit、または全 `A_i` の radical membership が成立した場合だけ正方向に進む。
- GF pass は `DETERMINANTAL_GF_SCOUT_PASSED`、QQ conditions pass でも `DETERMINANTAL_CONDITIONS_CERTIFIED_DIRECT_LIFT_PENDING` とし、いずれも nonterminal である。
- 条件不成立は `DETERMINANTAL_SUBSET_INCONCLUSIVE` とし、non-unit theorem へ昇格しない。
- inventory は `DETERMINANTAL_INVENTORY_COMPLETED` で、数学的 theorem status ではない。

policy は `sr2v-determinantal-cegar-policy-v1` として exact-key/self-digest 化し、coefficient scope、full row-universe digest、selected-entry digest、minor schedule、radical target、round/minor/term/certificate caps を request と fingerprint に結合した。

## 4. toy exact 検証

1. QQ の正例: scalar-associate row を除去し、entry-unit と radical 条件から determinantal pass を得て、直接構成した `J` の saturation が unit であることを照合。
2. 負例: 条件が不成立で、直接 `J` も proper のままであることを照合。
3. minor-unit shortcut: localized minor ideal が unit になり、直接 `J` も unit であることを照合。
4. minor cost cap: 次の minor の積項数上界が cap を超える場合、乗算・materialization 前に `SOFT_RESOURCE_LIMIT` 境界へ入ることを照合。

## 8. supervisor と履歴認証の補強

`sr2v-runtime-binding-v1` の attempt history load は、hash-chain の構文検査だけでなく worker protocol を再生する。

- `REQUEST_VERIFIED` は唯一かつ最初の worker message でなければならず、digest は request envelope/result/manifest と一致する。
- terminal worker result は唯一かつ最後でなければならない。
- `details.worker_result` は authenticated event の result message と canonical-exact に一致する。
- authenticated `WORKER_FINISHED.method` は verified request の `method` と一致する。イベントと result の双方を改ざんして hash-chain を再構成しても、request と不一致なら拒否する。
- method×status×GF/QQ scope、determinantal certificate/inventory digest、`direct_J_lift_verified=false` を request policy に再結合し、同じ method の汎用 `COMPLETED` への再ハッシュ改ざんも拒否する。
- legacy process audit は `sage-eval` と worker command に加え、process-table の `comm` が exact に `Singular` の standalone child も残存扱いする。
- legacy generation は従来の検証境界を維持する。

これにより、あとから method/certificate field を足したり、異なる method の成功を装ったりする経路を閉じた。

## 10. 第一論文化への判定

今回の成果で、従来の「stage 7 は chart saturation で停止し、仮説を評価できない」という計算ブロッカーは解消した。しかし stage 7 の選択 row だけでは十分条件を満たさず、補助イデアルの full unit theorem は得られていない。よって第一論文の証明本文へ unit-ideal 結論を入れる段階ではない。

次の唯一の計算ゲートは candidate-driven expansion とする。

1. cost order で次の source row 185 だけを、stage 7 と同じ 100,000 / 40,000 caps の inventory-only request で評価する。これは combined stage 8 の実行許可ではない。
2. row 185 の entries/minors を stage 7 の localized entry/minor bases で normal-form 評価し、exact に ideal を拡大するか確認する。同時に non-unit basis から評価可能な prime/component candidate の抽出を試みる。
3. row 185 が新情報を持たなければ、543 unique rows を一括多項式化せず streaming し、candidate を破る最小 cost row を探索する。
4. 選んだ row と minor の根拠・digest・順序を新 request/policy/fingerprint に固定し、minor-only、次に entry-only を別 attempt として実行する。
5. 新 GF stage は追加 row が既存 component を実際に切る場合だけ実行し、GF 条件が正方向に通った場合だけ QQ exact run と independent lift verification に進む。

禁止事項:

- 根拠のない stage 8 追加。
- 全 543 rows または全 `2 x 2` minors の一括 materialization。
- 同一 timeout fingerprint の再試行。
- GF pass を QQ theorem に昇格すること。
- 失敗済み localizer 分解を再発明すること。

candidate-driven gate でも exact escape row が得られない、または bounded resource 内で前進しない場合は、frozen inputs、全 attempt、証明境界、必要資源を resource-open として正式記録する。これは失敗の隠蔽ではなく、第一論文の claim を守る正当な終端である。
